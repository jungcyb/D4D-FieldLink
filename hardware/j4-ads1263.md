# AM64x SK J4 to ADS1263_EVB digital interface

This is the new ADS1263-only wiring. Keep the ADS8688 wiring on J9 unchanged.

| AM64x SK header | Board signal | ADS1263_EVB pin | ADS1263 signal |
|---:|---|---:|---|
| J4-40 | RPI_SPI1_CLK | 6 | SCLK |
| J4-35 | RPI_SPI1_D1 (controller output) | 5 | DIN |
| J4-38 | RPI_SPI1_D0 (controller input) | 3 | DOUT |
| J4-12 | RPI_SPI1_CS0 | 8 | CS# |
| J4-7 | RPI_GPIO0_35 | 4 | DRDY# |
| J4-15 | RPI_GPIO0_32 | 2 | RESET# |
| J4 GND | DGND | 7 | START (hold low) |
| J4 GND | DGND | 1/11/12 | digital ground |

The current bench uses an external 3.3 V supply and a common ground with the SK
(confirmed 2026-10-10). The activation script defaults to external power and
does not change header power. Do not connect the external supply output and
J4-1 together. The user reports that the module generates its analog 5 V
internally; actual AVDD has not been measured. ADS1263 requires 4.75-5.25 V
between AVDD and AVSS independently of DVDD.
Do not raise DVDD or expose the SK SPI inputs to 5 V.

For the former J4-1/J4-6 header-powered setup only, explicitly pass
`activate_ads1263.sh start header` (and `stop header`). This controls the
TCA9538 `RPI_PS_3V3_En` line. A GPIO enable state is not a voltage measurement.

SysConfig locks the corresponding SoC pads to SPI1 and GPIO0 lines 35/32.
SPI is mode 1 with a 4.5 MHz target (~4.167 MHz from the configured 50 MHz input
and SDK divider, not a measured clock), with D1 as output and D0 as input.

Linux conflict audit: MAIN_SPI1 is disabled in the live device tree and the
selected SPI1 pads, GPIO0_35, and GPIO0_32 are unclaimed. J4-37/GPIO0_41 was
deliberately rejected because the stock Linux eQEP0 pin group owns its pad.
